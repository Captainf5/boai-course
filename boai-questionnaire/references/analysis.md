# 从答卷到学员现状判断

## 先确认口径

客户、班次、学员问卷版本、课前/课后证据、业务日期/提交日期、提取截止时间、完整分页、重复/测试/空答。重复依据不足时标为疑似，不删除相同选项的不同答卷。姓名选填时，空姓名不是无效答卷，同名也不代表同一人；公开报告不展示姓名。来源坐标用Base＋Table＋Field，克隆表的相同字段ID不代表相同语义。

只围绕本次学员答卷分析；组织方的既有资料作为背景单独标来源，不再另收负责人卷。统计区分答卷份数与去重人数、有效分母与总回收数；多选可以超过100%，但超选和矛盾选项需标记，例如“可安装”与“禁止安装”同时选择。旧版题意不同不能按题号硬合并。按manifest的field_id→导出列名映射读取数据，题目显示标题可能与底层字段名不同。

不把AI使用频率当实际能力、不把谨慎当抗拒、不把学习意愿当落地条件。不把期待、客户自述目标或未经验证的效率数字当成果。没有数据不出结论；缺数据可以出“准备缺口及建议”。

## 分析输出

默认主报告面向甲方培训管理者，回答“学员目前是什么状态、差距在哪里、为何影响业务应用、培训应重点改变什么”。不能用问卷选项统计、建卷流程说明或讲师备课清单替代学员分析。统计是论据，页标题应写有证据支持的判断。

1. **一句话判断**：本次学员的岗位背景、能力起点与主要应用差距；证据只覆盖个人时不得写成全班特征。
2. **3–5条核心结论**：学员现状判断→匿名证据→业务含义→培训重点。交叉分析AI自评与具体任务做法、产出要求与现有标准、使用环境与任务可行性；未证实的联系标为待验证假设，不编造成因。
3. **学员画像与差异**：岗位/任务、行为能力层次、核心诉求、应用条件。仅在真实样本支持时分群；不虚构能力分数、雷达评分、采用意愿、群体比例或代表性。
4. **培训重点与评价**：回应主要差距，说明应观察的作品表现；课前自评不能直接作为课后成效。没有前后可比数据不计算增益。
5. **内部备课附件**：备课调整表、案例资料卡和材料缺口另存内部文件，默认不占据甲方汇报主线；需要时再附给讲师。保留既有资料位置与许可，只追问关键缺项。

可用页纲：管理摘要→岗位画像→能力状态→工作痛点→落地障碍→培训重点→证据边界。甲方主报告不写CLI、Skill安装、邮件回执等执行信息；技术验收单独保存。模拟数据必须明确标为汇报样稿，不将其改写成贵单位真实情况。

需求、推断、建议要分开。甲方目标与学员多数需求不同时明确权衡；小众高价值场景不能仅因票数低被排除。不同月份、客户或版本采样不均衡时不做增长趋势或优劣排名。

## 结论表达：直接、具体、客观

- **每页一个主判断。** 结论页标题直接说明学员当前状态、关键差距或首要约束，不只写“AI水平分析”“数据情况”等栏目名；正文按“判断 → 关键证据 → 业务含义 → 培训重点”展开，避免逐题复述。
- **细节充分就深入判断。** 把具体任务步骤、输入资料、期望成品、行为自评与环境限制相互核对，指出差距发生在哪个环节、影响哪种产出、应该优先改变什么。样本足够时说明不同岗位或能力群体的差异，不用笼统平均值抹平差异。
- **明确程度与证据匹配。** 证据已充分支持的判断直接写，不反复用“可能、或许、一定程度上”稀释结论；只支持自评、个别样本或假设的，在判断旁简短注明范围与待验证点。细节更多不自动等于因果成立，不编造精确评分或效果。
- **对事不对人，客观不含糊。** 可以明确指出流程缺口、能力差距和使用限制，但不批评甲方，不推断其重视程度、管理水平或学员态度；同时写清已有基础。不同原因要区分，不把环境限制归因于能力不足，不把未上传等同未准备。少用“落后、混乱、不重视、不配合、能力差”等标签，也不为讨好甲方回避有证据的问题。
- **改进点可执行。** 只保留3–5个最影响培训与业务应用的结论，说明优先顺序的证据；“加强赋能、提升认知、进一步优化”等套话必须落到具体任务或作品表现。

写法示例（仅在对应证据成立时使用）：

| 空泛或归责表达 | 客观且明确的表达 |
|---|---|
| 学员AI能力有待提升 | 学员能生成初稿，但尚不能独立核验关键数字来源；培训重点应放在结果校验。 |
| 甲方准备不足、不够重视 | 已收到任务说明，尚缺可用于练习的脱敏样例与合格成品；当前无法验证案例适配性。 |
| 公司系统落后，影响学习 | 现有终端禁止安装客户端；实操需要采用已获准的浏览器路径。 |

## 通往归藏PPT

先存`analysis.md`（含来源与口径）、`metrics.json`、`deck-outline.md`（逐页结论与证据）。报告默认汇总、匿名，去掉姓名、手机号、邮箱及不必要的客户机密。原始答卷不是幻灯片附件。模板里保留范围和未知项，方便合作伙伴理解结论的适用边界。

`workflow.py analyze`只做结构化统计，文本题的主题归纳与资料卡需要Agent读取实际回答；脚本不生成虚构课程结论，也不判断业务材料已获授权。
