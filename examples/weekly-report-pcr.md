# 通用工作周报：从一句话到可复用 Skill

状态：教学设计草案 v01，供其他 Agent 制作 PPT；尚未完成课堂试讲和 WorkBuddy 端到端实测。
更新时间 / 核对日期：2026-11-02。
来源：冯博10月课程录音复盘、用户确认的周报质检案例方向、博AI案例制作与提示词工厂的方法。原始录音和内部报告不公开。
数据性质：下列组织、人员、任务、证据摘录和日期均为教学模拟；不是客户真实工作记录。

## 给 PPT 制作 Agent 的交接说明

请把本文制作成一套可直接带练的教学 PPT，主题为“用 PCR 做出一份可信、可交付、可复用的工作周报”。面向普通办公人员，不要求编程，不限定客服或某个行业。不要另换案例，也不要加入新的概念体系。

- 主线是一个案例逐步升级：人先判断 → P 说清要求 → C 补齐资料 → R 实际动手 → Skill 固化 → 换人换资料复测。
- 保留表格中的任务编号、日期、事实冲突和验收口径。它们是练习的核心，不能只剩框架图。
- 学员页只放材料、任务和验收要求；“教练答案”放讲师备注或最后揭晓页，不要提前展示。
- 长提示词放备注或配套材料，屏幕只放操作目标和关键句。每阶段必须有学员操作时间，不能全部由讲师演示。
- 不编造 WorkBuddy 界面、截图、邮件回执或运行成果；没有实测截图时用明确标注的流程示意。
- 核心课建议120分钟，时间是试讲前估计。可选邮件发送实验另加10分钟，不挤占作品互评。

## 一、案例任务：主管只给你三分钟

你是一个部门的项目协调人员。周五要把本周零散记录整理成一页周报，让主管判断：**本周真正交付了什么，下周最需要协调什么？**

困难不是“不会写漂亮的话”，而是任务台账、群消息和验收记录可能不一致。“做了”“提交了”“验收了”不是同一个状态。

最终交付四样：

1. 一页工作周报：核心判断、已交付成果、风险与支持需求、下周行动。
2. 一份核查表：结论对应任务编号、证据和不确定项。
3. 一个可在手机和电脑阅读的 HTML 周报，以及待发送邮件草稿。
4. 一个用第二周资料验证过的周报 Skill；没有运行成功，只能称为草案。

核心知识点只有 PCR：

| 层 | 本案例中解决什么 | 学员必须做出的动作 |
|---|---|---|
| P：Prompt | 到底让 AI 交什么 | 正向说明、反向拆解与追问、固定字段复用 |
| C：Context | 凭什么判断完成、风险和优先级 | 提供原始记录、规则、参考成品；解决冲突并引用证据 |
| R：资源与权限 | 能读哪里、能写什么、能否发送 | 核查工具和授权，生成文件，遇到未授权动作停下 |

一句课前话术：**“今天不比谁的提示词最长。我们比谁能让主管看清事实、作出决定，并让同事下周接着用。”**

### 材料 C：周报口径与边界

1. “已交付”要求有验收或确认依据；提交、上传、初稿不等于已交付。
2. 截点前存在冲突时，优先采用较新的明确验收记录，同时保留冲突说明，不覆盖原台账。
3. “到期未交付”指计划截止日不晚于10月30日，且截点前没有通过验收。未到期事项不能混入。
4. 必须区分事实、判断、建议。支持需求可以提出建议；未经确认的新日期、协作人不得写成已承诺事项。
5. 无工时、上周对照或满意度数据，不得写“效率提升”“环比改善”“全员满意”等结论。
6. 不按字数或忙碌程度评优；主管最需要知道成果、影响、需要他作出的决定。
7. AI可以读取本次指定材料，在新建输出目录生成文件；不得改写、删除源文件。邮件默认只起草。

### 材料 D：参考成品的形式

以下是另一个模拟周期的结构示例，只学写法，不得把其事实搬进本周。

> **核心判断**：新员工材料已可用，排班试点仍待确认覆盖范围；下周先确定试点人员。
>
> **已交付**：完成入职指引并通过验收，供新人办理入职时使用。【样例任务A】
>
> **需支持**：排班试点覆盖哪些岗位尚未确定。建议主管确认试点范围后，再由执行人排期。【样例任务B】
>
> **下周行动**：按确认范围更新排班表；具体日期待范围明确后确定。

这份样例是“标的物/对标成品”；A、B是输入资料；C是判断规则。三者不能互相替代。

## 三、课堂流程：四轮升级，每轮都交作品

每组3人：操作员、事实核查员、主管。每轮轮换角色。主管只问“我该据此作什么决定”，事实核查员必须指出证据编号。每次修改保留上一版，展示具体改进。

### 开场：先由人判断，再让 AI 写（10分钟）

先只发材料A、B，不公布教练答案。

**讲师说：**“先不用AI。圈出你愿意向主管承诺已完成的事项，再选出一个最需要他协调的问题。写下依据。”

每人独立2分钟，两人交换依据3分钟。之后把同样的材料交给AI，只输入：“帮我写本周工作周报。”保留实际输出作为V0，不预设AI一定犯错。

**现场检查：**学员能否分辨“台账写完成”和“有验收证据”；能否给出判断依据，而不是只讲工作量。

### 第一轮：P——从会提要求到会反推标准（25分钟）

#### 1. 正向初阶：五要素

让学员修改下面提示词中的读者和目标，然后实跑一次：

```text
背景：我是部门项目协调人员，整理10月26日至30日的工作周报。
角色：请担任重视事实核验的工作助理。
任务：根据我提供的材料，让主管看清已交付成果和需要协调的问题。
格式：核心判断一句；已交付成果；风险与支持需求；下周行动。正文不超过600字，核查表另列。
限制：不把提交写成验收；不编数字、原因或承诺；每项关键判断标注任务ID，缺失信息明确标注待确认。
先复述目标，再写一句核心判断供我核对，确认方向后扩成全文。
```

讲师只追问：“你加的哪一句要求，改变了哪一句输出？”不能只回答“更专业了”。

#### 2. 反向初阶与高阶：拆成品、查盲区

发材料D，让学员用以下指令倒推可复用标准：

```text
拆解这份参考周报：服务谁、帮助什么决策、使用什么结构、怎样证明完成、哪些规则可复用、哪些事实不能复制。
据此给我一条可复用的周报提示词。不要生成本周没有证据的结论。
```

再让“主管”给出质疑，操作员使用：

```text
先不要重写。分别从主管、执行人、核查员角度，找出草稿最值得质疑的3句话。
逐句列出原句、证据或缺口、应删除/收窄/保留的建议。
需要追问时一次只问一个，并附推荐处理方式；材料中能查到的自己查。
```

**正向高阶的落点：**把“完成”定义说清；先核事实再写判断；保留好句、修正失实部分。不要为炫技堆术语。

**现场验收：**交V1和一条“原句→修改句→修改依据”；如果V0已经正确，说明新提示词稳定了什么标准，不人为制造错误。

### 第二轮：C——资料齐不齐，决定判断靠不靠谱（20分钟）

发材料C。保持上一轮提示词主体不变，补入规则与样例，再产出V2。

```text
先建立核查表：任务ID｜原台账状态｜验收证据｜截点状态｜是否到期未交付｜冲突说明。
以规则解释冲突，保留证据编号；缺信息时不要补造。
核查后重写周报。分别标出事实、判断、建议，建议中的新日期和协作人必须标待确认。
```

**讲师说：**“现在别急着润色。先告诉我哪一项看似完成其实没有交付。你缺的是更漂亮的提示词，还是一条能作判断的证据？”

**现场验收：**至少发现W05冲突；给出可追溯的完成数量；把需要主管协调的事项写成可回答的请求。涉及计数时不能只相信AI自述，要逐项人工复核。

材料少时粘贴是C；资料多时从文件读取也是C。能否读取该文件则属于R。两层要分清。

### 第三轮：R——在 WorkBuddy 里交出文件并守住边界（25分钟）

课前由讲师将本文的A、B合成 `input/第一周记录.md`，将C放入 `reference/周报规则.md`，将D放入 `reference/参考周报.md`。均保留“教学模拟”标签。

```text
周报练习/
  input/第一周记录.md
  input/第二周记录.md       # 复测时才提供
  reference/周报规则.md
  reference/参考周报.md
  output/                 # 新结果存这里
```

在 WorkBuddy 选择本次练习目录，核对当前工具可用性和权限模式，使用带确认的权限方式。界面名称以现场版本为准。不要用真实客户资料练习。

```text
请读取本次练习目录中的第一周记录、周报规则和参考周报。
只处理第一周。先核事实，再输出：
1. output/第一周-周报.md
2. output/第一周-核查表.md
3. output/第一周-周报.html（单文件、离线可读、手机和电脑可读）
4. output/第一周-邮件草稿.md（收件人待确认）
不得修改或删除输入与参考文件，不覆盖已有结果，存在同名文件时另存版本。
不得自行连接其他系统或发送邮件。工具或授权不足时说明具体缺口，不声称完成。
完成后列出实际生成路径，并检查正文、核查表与HTML的事实一致。
```

**讲师说：**“能在聊天里写，不代表能在你电脑里保存；能保存，也不代表能替你发送。今天把这三件事分别验收。”

学员实际打开HTML，查看窄屏和宽屏；核对输出目录文件存在，输入文件内容与课前副本一致。核查员挑一条报告结论反查材料。

**边界解释：**提示词中的限制是行为约定，不是系统访问控制；选择工作目录也不等于形成隔离沙箱。实际可执行范围还取决于宿主工具、系统权限、连接器授权和用户批准。Skill本身不赋予权限。

**可选发送实验（另加10分钟）：**仅当现场已有可用邮件连接器时，操作者提供本人控制的测试邮箱，核对收件人、主题、正文和附件后，明确批准这一次发送。以服务返回记录及测试邮箱实际收到为证据。不可用就保留草稿并标记未测，不要求学员提交密码，不冒充发送成功。本教学文档本身不授权任何真实发送。

### 第四轮：合＋Skill——让同事下周也能用（25分钟）

“合”是把稳定结构变成字段模板，便于重复使用；不是把几个AI回答拼在一起。

```text
请把刚才通过核查的流程整理成可复用周报Skill草案。
可变字段：统计周期、截点、输入资料位置、读者、输出目录、可选测试收件人。
固定步骤：检查输入→统一口径→核查冲突→生成周报→生成核查表和HTML→检查结果→起草邮件。
首次缺失的必要字段先问；能从资料查到的不重复问。没有源资料时不编造周报。
保留原件，默认只起草邮件。收件人和本次发送内容须另行确认，不能继承上次发送许可。
不要把本周业务数据、邮箱、账号凭据或机器绝对路径写死在Skill里。
输出SKILL.md及必要的规则、模板文件；遵守当前Agent的Skill规范。
```

这是学生封装任务，需按实际宿主规范创建和安装。生成一个叫SKILL.md的文件不等于它已被成功识别和调用。

接下来交换操作员，另开新会话，加载Skill，只给第二周资料及必要参数。第二位同学不得复制第一周的完整对话。

**现场验收：**新会话能按预期调用；周报日期正确；W05已转为完成、W04仍待验收；不沿用第一周结论；保留原件；没有自动发送。

### 展示与复盘（15分钟）

每组展示90秒，只讲三件事：“我们改对了哪一句”“证据在哪里”“下周谁能接着用”。同组成员轮流回答，不让操作员一个人包办。

最后每人写一句：**“回到岗位，我准备把____交给AI；我负责核查____；涉及____动作时必须确认。”**

## 五、教练答案与现场评分——禁止提前发给学员

### 第一周事实底线

- 截点前已交付：W01、W02、W03，共3项。
- 到期未交付：W04、W05、W06，共3项。W05上传完成不等于归档验收完成。
- 未到期且未交付：W07、W08，共2项。不应混入逾期统计。
- 分母必须说清：任务池共8项，其中本周截止应交付6项、已交付3项。不要把3/8不加说明称为“按期完成率”；W01—W03验收日期不晚于各自截止，按上述本周应交付口径可写3/6。
- 没有任何工时或上周数据，不能证明效率提升、产能提升或环比改善。
- 主管支持可聚焦试用名单、评审参会人确认；W05首先需要补材料。没有影响与资源数据，不能宣称某项一定造成重大损失，也没有唯一正确的优先级排名。

**核心判断示范：**“本周到期应交付的6项工作中，3项已有完成确认；知识库试用、资料归档和流程评审尚未完成交付，下一步需分别解决名单确认、附件补齐与参会人确认。”

**行动句示范：**“建议主管协调相关部门确认W06参会人，由周宁据此重排评审时间；新日期待确认。”

**不合格句示范：**“各项工作稳步推进，团队效率显著提升，下周持续加强协同。”它既没有证据，也不能帮助主管作决定。

### 第二周事实底线

- 本周任务池6项；本周到期4项：W04—W07。
- 已交付3项：W05、W06、W07；到期未交付1项：W04。
- W08、W09未到期且未交付。W09责任人缺失，应明确待确认。

- 不能把第一周与第二周不同任务池的完成占比变化直接解释为团队效率提升。
