# 博AI PPT 工作室 · WorkBuddy实现

v2.0.0（2026-10-12）= 原 boai-ppt（slidep 工程化执行层）融合 boai-ppt v2.0.1（大纲共创/引导交互/信息量模式层）。一套 Skill 走完全程：**共创大纲 → 逐页脚本 → slidep 制作 → 批量维护**。

**本 Skill 是本套件的 PPT 入口**。博AI品牌任务按本文件锁定模板执行；非博AI品牌的 PPT 需求也走环节一/二工作流，版式参数（色板/页脚/字体）按用户当场指定的模板或参考文件，不套用博AI红。

## 铁律（用户亲口确认，不可违反）

1. **不列页码**——任何页面都不出现页码。
2. 页脚署名写 **"博AI · Agent时代工作坊"**，绝不写"博派AI"。
3. 右侧竖排 "Embrace AI, Empower U" **整行直下不换行**：`whiteSpace: 'nowrap'` + `transform: 'rotate(90deg)'`，旋转前盒子必须整体落在画布内（lint 按未旋转盒子判溢出）。
4. 主色只锁定一套：红 `#E8443A` + 白底，禁止引入第二个主色调。
5. 卡通小人 = **固定讲师IP BOBO**：红衣+戴眼镜+黑发男孩，跨课程延续，不换形象。
6. **不编造**数据、案例效果或来源；缺失材料标"待补充"，模拟数据注明性质。
7. 修改已有 PPT：**原版保留，新版独立命名**；每次改前留时间戳备份（见 batch-workflow.md）。

## 入口判断：用户在哪个环节开始

用户只说"开始做PPT"时，简短询问一句："这次是先一起讨论大纲，还是直接制作/修改 PPT？"可同时读取已给材料。已明确的选择直接沿用，不重复问。

- **先讨论大纲** → 环节一，不擅自生图或制作整套。
- **已给逐页脚本/课纲要求制作，或要改现有 PPT** → 环节二。
- 两环节可往返；大纲经用户确认后再进制作，不重复要授权。

引导原则：每轮只解决最关键的缺口，1–3 句话说明"当前进展/我能替你做什么/你下一步只需做什么"；只给当前相关 2–3 个选项，推荐项优先；接受数字、自然语言或"你决定"。阶段切换、代表性样页出现、关键歧义时才引导，不每页打断。详细话术表见 `references/co-creation.md`。

## 环节一：大纲共创与逐页脚本

读取 `references/outline-template.md`（五项格式约定+可复制提示词）。

1. 先读用户已有材料，仅追问缺失且影响设计的要素（听众/时长/学习目标/必保留内容），不发长问卷。
2. 从学习目标倒推主线，按因果、递进、转折组织页面，不机械按原文顺序分页。每页五项：**标题、内容、画面、金句、人物**。页数由用户要求决定，一次交付全部，不用"同上"占位。
3. **出课纲前必须确认关键概念页设计**（用户硬性要求）：列出所有"关键概念页"候选，通过宿主可用的提问界面或自然语言集中确认页型（页型菜单见下节与 design-tokens.md §4）。人物页属于教学设计——只有人物确实参与解释才用，不做贴纸装饰；集中确认关键页与总体比例，不逐页机械询问。
4. 以完整 Markdown 文件交付逐页脚本。

## 制作环境检查

先检查 slidep 是否可用；只有已安装且命令帮助与参考资料吻合时才执行下述命令。缺少 slidep 时，使用宿主可用的 PPTX 制作工具，沿用设计规则并逐页渲染核对；无制作工具时仅交付逐页脚本并说明缺口。手绘页需要图像生成能力，没有时保留构图说明，不伪称已生图。批处理脚本需要 Bash，不直接在 PowerShell 中执行。

## 环节二：制作与批量修改（slidep 工程化执行）

### 工作流 A：新建课程 PPT

1. 写 STORY.md（叙事骨架）与 DESIGN.md（引用 design-tokens.md 的 token）。
2. `slidep create <name>.pptx` → 用宿主可用的文件预览打开检查。
3. 逐页：写 `slides/NN.slide` → `slidep lint` → 修复 → `slidep upsert-dsl`。每 3 页一批。**先核对代表性样页，再批量制作**。
4. 卡通概念页走工作流 C。

### 工作流 B：批量修改（核心复用场景）

"换署名/换颜色/统一改样式/修溢出"等跨页修改，命令模板与踩坑清单见 `references/batch-workflow.md`，脚本用 `scripts/batch_upsert.sh`：

```bash
sed -i "s/旧值/新值/g" slides/*.slide   # 先 grep 确认命中数
bash scripts/batch_upsert.sh "<项目目录>" "<pptx文件名>" <总页数>   # 必须带 --page-index，后台跑
```

要点：upsert 不加 `--page-index` 会追加而非替换；40+ 页使用宿主支持的后台任务机制；没有后台能力时分批执行；先 lint 全过再 upsert；**upsert 后必跑 `<a:t>` runs 关键词抽检**（防吞拉丁 bug，见 batch-workflow.md 踩坑7）；改完把用户新确认的风格偏好回写 design-tokens.md。

### 工作流 C：BOBO 卡通小人概念页

ImageGen 生成全幅插图再嵌入。IP 描述、B2 手绘风 prompt 模板、物理隐喻构思法、量产踩坑、白化修补术全部见 `references/cartoon-page.md`；构图实例库见 `references/handdrawn-scenes.md`；风格参照图在 `assets/style-ref/`。嵌入时标题/红条/竖排英文仍用 DSL 画，保持模板骨架统一。

## 页型体系与配比

| 页型 | 适用内容 | 制作方式 |
|---|---|---|
| A 商务咨询页 | 框架/模板/数据/评审/对比 | DSL 卡片/表格/流程，白底红强调，**原生可编辑对象优先** |
| B 卡通小人概念页（B2手绘默认） | 抽象概念/方法论理念/人机关系/学习动员 | ImageGen 全幅插图，见 cartoon-page.md |
| C 巨字金句高潮页 | 每章 1 个视觉高潮 | 全红反白或三色巨字 |
| D 截图证据页 | 实操/案例/社会证明 | 真实截图+红色描边框+一句点评 |
| E 章节页 | 章节分隔 | 全红底+白色巨字章节号+白竖排英文 |

配比共识（2026-10-05 起多次验证）：**严谨信息页为主体，手绘概念页点睛（默认建议约占 20%，以本次教学目标和用户确认为准），避免连续出现**；卡通太多显不专业。卡通页转商务页：按核心框架重写 DSL 卡片版式，lint→upsert 原位替换，旧资产保留不删。节奏：概念→案例→实操→总结；每章 1 个 C 类高潮页。

## 信息量模式

未指定时建议"均衡教学"，与入口确认合并，不重复提问；连续修改沿用已选模式。

- **精简讲授**：突出核心判断、关系和记忆点。
- **均衡教学**：补必要条件、判断依据或一个短例子。
- **详细复习**：增加方法清单、案例对照与边界，保持投影可读。

超容量内容合理拆页或放备注；信息密度不能靠缩小字号提升；详细讲法放备注，但重要上屏信息不能全移到备注。

## 交付前检查

- 对照逐页脚本：重要内容无遗漏，事实与模拟标记准确，人物页符合已选比例。
- 标题/字体/配色/边距/BOBO 一致；箭头关系正确；文字可读不溢出；**逐页看渲染结果**，不能用"保存成功"代替实际打开验证。
- 方法论页必带"提示词案例条"（design-tokens.md §5）。
- 修改版检查原生对象、备注、媒体是否保留；手绘图内文字是位图，向用户说明编辑限制。
- 未获验收标"待审阅"；说明实际完成、验证情况和实质限制。
